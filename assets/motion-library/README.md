# 自媒体备用动效库

这个目录保存和管理用户提供的动效代码与对应截图，供安装本 Skill 的分镜项目按需使用。

## 调用边界

1. 制作分镜素材、口播插入画面、动态图文包装和独立分镜视频时，按照 Skill 的动效素材库规则，根据当期文案和画面内容自动检查并保守选择合适的动效，不需要用户再次点名。
2. 自动匹配只在动效能够帮助表达并自然融入当期整体风格时使用；没有真正合适的素材时不调用，不为凑数量添加。
3. 片头、开场、封面、真人出镜整片和其他类型任务，只有用户明确要求“从动效库里选择”“调用动效库”，或直接点名某项动效时才使用。
4. 动效库不替代各类视频原有的默认模板；正式接入后必须统一为当期的字体、配色、布局、安全区和动效节奏。

## 固定整理方式

每项动效建立一个独立文件夹，文件夹名称为：

```text
{三位编号}_{中文名称}/
```

同一项动效的所有内容都放在这个文件夹中：

```text
001_左右摇摆数字卡/
├── 001_左右摇摆数字卡_截图.png
├── 001_左右摇摆数字卡_代码.html   用户提供代码后保存，扩展名按原代码类型确定
└── README.md                       来源、用途、代码状态和备注
```

## 保存规则

1. 用户给出代码后原样保存，不主动改写、适配、注册或渲染。
2. 对应截图与代码必须放在同一个动效文件夹，不再拆分“参考素材”和“待整理源码”目录。
3. 代码可能包含多个文件时，仍放在同一动效文件夹内，并保留原始文件名或使用清楚的功能名。
4. 有来源网址、作者、许可证或使用限制时，写入该动效文件夹的 `README.md`；无法确认的信息标为“待确认”，不得猜测。
5. 新素材依次使用 `002`、`003` 等编号，并同步更新根目录的 `动效登记表.md`。
6. 除非用户另外要求，不为归档素材生成 Remotion 组件、预览视频、静帧或其他派生文件。

## 交互动效用于视频时的通用规则

1. 用户提供的代码如果依赖点击、悬停、聚焦、按下、拖动、滚动、输入或其他网页交互，归档时仍保留原始代码，不提前改写。
2. 动效正式用于视频时，把交互状态转换为按视频时间轴自动触发，不等待观众操作。
3. 自动触发顺序必须保留原交互的语义，例如“默认状态 → 触发反馈 → 状态变化 → 保持或退出”，不能只播放无意义的循环。
4. 具体触发帧、持续时间和退出方式按当期文案、字幕时间码、镜头时长与画面节奏确定。
5. 分镜类任务的自动匹配范围和其他类型任务的调用边界，以当前项目规则和本 Skill 的 `SKILL.md` 为准。

## 视频调用时的中文文字规则

1. 归档阶段保留素材原有的数字、英文和演示文字，不改写原始代码。
2. 某项动效正式用于视频时，动效里的可见文字必须根据当期文案重新填写，不能沿用示例中的 `Generate`、`Generating`、数字 `6` 或其他无关占位内容。
3. 用户文案默认以中文为主。调用时必须重新检查中文字体、字形完整性、字号、字重、字距、行距、对齐、换行和承载区域，不能直接沿用为英文字母设计的宽度与间距。
4. 中文字体优先使用项目已有且授权明确的字体，并遵守当前项目字体规则；必须确认所用字体覆盖当期全部汉字、数字和标点，不得出现缺字、替代字形或字体回退造成的风格断裂。
5. 逐字、逐字符或字母延迟动效改为按照中文字符和语义节奏拆分；标点是否参与动画根据阅读节奏决定，不能机械套用英文 `nth-child` 间隔。
6. 文案较长时，优先缩短画面文字、合理换行、扩大承载区域或拆成多个状态；不得为了塞入原组件而把中文缩得过小、挤压字距或让文字超出边界。
7. 最终排版必须遵守当前视频类型的文字安全区、字幕安全区和平台按钮安全区，并在正式制作时检查关键帧中的文字完整性。
